# 1.2 数据分析 — 传感器数据加载、清洗与可视化

## 概述

**1.2 数据分析**是《机器人与人工智能》课程体系的第一步实操环节。核心理念是：**训练任何模型之前，先理解你的数据长什么样**。

程序 `data_analysis.py` 位于：
`src/ml_basics/ml_basics/data_analysis.py`

它用机器人最常见的 3 类传感器数据（陀螺仪、加速度计、编码器）演示了标准的数据分析流水线。

---

## 程序架构：四步流水线

### Step 1 — 生成模拟数据

在没有真实传感器的情况下，程序模拟了一个简单场景：

> 机器人走了 10 秒，IMU 和编码器以 50Hz（20ms 间隔）记录了 500 个采样点。

| 传感器 | 模拟方式 | 数据特征 |
|--------|----------|----------|
| 陀螺仪 Z 轴 | `0.1 × sin(ωt)` + 零偏 5°/h + 噪声 σ=0.001 | 正弦摆动，有微小常值偏置 |
| 加速度计 X 轴 | 恒定 0.05 m/s² + 零偏 + 噪声 σ=0.01 | 基本平直，随机噪声均匀 |
| 编码器速度 | 0.1 m/s + 小幅摆动 + 噪声 σ=0.02 | **10% 的采样点会随机打滑**（速度骤降到接近 0） |

**关键设计意图**：模拟数据并非理想状态，而是刻意注入了真实传感器常见的问题——

- **零偏 (bias)**：传感器即使静止也会有微小输出
- **随机噪声**：测量不确定性
- **打滑 (slip)**：轮式机器人实际运行中的典型故障模式

### Step 2 — 数据清洗

```
Z-score 异常值检测    →   |value - mean| / std > 3 标记为异常
去零偏               →   corrected = raw - known_bias
```

- `detect_outliers()` 函数用 3σ 阈值识别异常点
- 打印 3 路传感器各检测到多少异常值

### Step 3 — 特征统计

对清洗后的数据计算 4 个基本统计量：

```
均值 (mean)  ·  标准差 (std)  ·  最小值 (min)  ·  最大值 (max)
```

这些是后续课程（2.1 决策树）特征工程的起点——2.1 垃圾分类中提取的 12 维图像特征，本质上和这里的统计量属于同一套分析思路。

### Step 4 — 可视化

生成一张 **1200×1000 像素的六宫格图表**（3×2）：

| 位置 | 类型 | 内容 |
|------|------|------|
| 左上 | 折线图 | 陀螺仪 Z 轴角速度随时间变化 |
| 右上 | 直方图 | 陀螺仪数据分布（接近正态，中心略偏） |
| 左中 | 折线图 | 加速度计 X 轴随时间变化 |
| 右中 | 直方图 | 加速度数据分布（正态） |
| 左下 | 折线图 + 散点 | 编码器速度，**橙色散点 = 打滑点** |
| 右下 | 直方图 | 速度分布（**双峰**：主峰 0.1 m/s，次峰接近 0，由打滑造成） |

图表保存路径：`src/ml_basics/pictures/data_analysis.png`

## 图表解读指南

### 左列：时序图 (Time Series)

- **陀螺仪 (Gyro Z)**：蓝色细线，±0.01 rad/s 正弦摆动。能看出规律的周期性，说明机器人走路时身体有左右摇摆。
- **加速度计 (Accel X)**：绿色细线，基本平直，噪声均匀。说明机器人前进加速度基本恒定。
- **编码器 (Encoder)**：红色细线 + 橙色散点。正常区域在 0.1 m/s 附近，**橙色点是打滑瞬间**——速度骤降到接近 0。

### 右列：分布直方图 (Histogram)

- **三组数据都近似正态分布**——这是很多机器学习算法（如贝叶斯分类器）的基础假设。
- **编码器呈现双峰分布**：一个主峰在 0.1 m/s（正常行驶），一个矮峰在 0 附近（打滑点）。双峰或长尾分布提示数据中可能存在**异常模式或故障状态**，需要在建模前发现并处理。

---

## 关键学习点

1. **分析优于建模**：不理解数据就去训练模型，结果不可靠
2. **模拟数据的教育价值**：可以精确控制注入的故障模式（偏置、噪声、打滑），让学习者在受控环境中练习诊断
3. **直方图是数据质量的镜子**：正态 → 数据干净；双峰 → 存在混合模式；长尾 → 有异常值
4. **零偏是传感器固有属性**：IMU 坐标系静止时输出不归零，必须先标定（或从数据中减去已知偏置）

## 如何检测真实传感器

模拟数据适合教学，但在真实机器人上需要接入实际硬件。以下以 **NXROBO Spark 机器人**（ROS2 Humble）为例，说明如何替换模拟数据为真实传感器读数。

### 1. 识别可用的传感器话题

Spark 机器人启动后会发布多个传感器话题，用以下命令查看：

```bash
# 列出所有活跃话题
ros2 topic list

# 查看 IMU 话题的详细信息
ros2 topic info /imu
ros2 topic echo /imu --once

# 查看里程计话题
ros2 topic info /odom
ros2 topic echo /odom --once
```

### 2. ROS2 话题与程序变量的对应关系

| 模拟数据来源 | 真实 ROS2 话题 | 消息类型 | 提取方式 |
|-------------|---------------|---------|---------|
| `gyro_z` | `/imu` | `sensor_msgs/Imu` | `msg.angular_velocity.z` |
| `accel_x` | `/imu` | `sensor_msgs/Imu` | `msg.linear_acceleration.x` |
| `encoder_v` | `/odom` | `nav_msgs/Odometry` | `msg.twist.twist.linear.x` |

> 注：陀螺仪和加速度计通常来自同一个 IMU 话题，不需要分两个话题读取。

### 3. 修改方案：订阅 ROS2 传感器话题

将 `data_analysis.py` 改为从 ROS2 话题采集数据，核心代码结构如下：

```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import Imu
from nav_msgs.msg import Odometry
import numpy as np

class SensorCollector(Node):
    def __init__(self):
        super().__init__('sensor_collector')
        self.gyro_z = []
        self.accel_x = []
        self.encoder_v = []
        self.max_samples = 500

        self.imu_sub = self.create_subscription(
            Imu, '/imu', self.imu_callback, 10)
        self.odom_sub = self.create_subscription(
            Odometry, '/odom', self.odom_callback, 10)

    def imu_callback(self, msg):
        if len(self.gyro_z) < self.max_samples:
            self.gyro_z.append(msg.angular_velocity.z)
            self.accel_x.append(msg.linear_acceleration.x)

    def odom_callback(self, msg):
        if len(self.encoder_v) < self.max_samples:
            self.encoder_v.append(msg.twist.twist.linear.x)
        if (len(self.gyro_z) >= self.max_samples and
            len(self.encoder_v) >= self.max_samples):
            self.get_logger().info('Collection complete, processing...')
            self.process_data()

    def process_data(self):
        # 在这里放入原有的分析代码（数据清洗、统计、可视化）
        pass

def main():
    rclpy.init()
    collector = SensorCollector()
    rclpy.spin(collector)
    collector.destroy_node()
    rclpy.shutdown()
```

### 4. 实际运行步骤

```bash
# 终端 1：启动机器人底层驱动（如果尚未启动）
ros2 launch spark_base base.launch.py

# 终端 2：运行真实传感器数据分析
cd ~/Music/spark_humble
source install/setup.bash
ros2 run ml_basics real_sensor_analysis.py
```

### 5. 注意事项

- **话题名称可能不同**：Spark 机器人的传感器具体话题名取决于 `spark_base` 包的配置，需先用 `ros2 topic list` 确认
- **采样频率**：模拟数据用 50Hz，真实 IMU 通常也是 50-200Hz，编码器 10-50Hz。频率不匹配时不需要精确对齐，各自按收到的时间戳处理即可
- **时戳对齐**：可以用 `message_filters.ApproximateTimeSynchronizer` 做时间同步，但课程 1.2 阶段**不需要**严格对齐，各自按时序排列即可
- **零偏标定**：真实 IMU 使用前需静置标定，或直接读取 `/imu` 话题中已标定的数据
- **没有实体机器人？**可以用 `ros2 bag play` 回放录制的传感器数据包，实现"离线真实数据"分析
